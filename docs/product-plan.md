# Growmory 产品与功能整合方案

日期：2026-11-05。本文描述新版目标；不要求兼容历史数据，但实施时不主动删除当前账号或本地资料。

## 产品定位与工作流

面向独立 App 开发者的产品运营工作台。每个产品拥有一份可信知识库，版本、商店优化、营销内容和趋势数据围绕同一产品关联。AI 负责理解、生成与分析，人负责事实确认和对外发布决策。

主流程：连接 → 导入产品 → 确认产品事实 → 准备版本 → 本地化 → 发布 → 生成推广内容 → 收集数据 → 复盘 → 改进产品与 ASO。

导航（2026-11-05 体验改版）：工作台、产品、内容、待办；设置独立管理连接、AI 与备份，初始化作为接入向导。资料、版本发布、商店优化和数据表现围绕单个产品组织；全局数据总览采用统一时间范围的对比表，详情一次展示一个产品。工作台与待办从原记录推导系统提醒，手动任务单独管理。趋势指标按产品、日期、来源和地区展示，不能用工作区记录数量替代产品表现。实施与验收边界见 `experience-redesign-20261105.md`。

## 1. 初始化

1. 连接 AI Agent：提供 MCP 配置、连接检测、最近成功调用、读写权限；MCP 是外部 Agent 操作工作台的通道，站内生成需要单独配置模型服务。
2. 连接 App Store Connect：保存凭据，检测可访问 App；分开显示元数据读取、销售报告、分析报告和写入能力。一次读取成功不能代表全部权限可用。
3. 选择 App：支持批量选择导入，每个 App 创建一个产品；保存 Apple App ID、Bundle ID、平台、主语言和商店快照。名称、介绍、价格等候选值预览后采用，不从单一地区价格推断全球定价。
4. 导入数据：版本和本地化文案、ASO 原文、可用销售与分析报告；每项独立显示成功、无权限、待生成或失败。可重试，避免重复创建产品。
5. 完善资料：定位、目标用户、核心场景、功能、差异点、商业模式、价格口径、官网和品牌语气。
6. 建立知识库：按导入资料生成待确认文档；人工确认后才能作为 AI 的正式事实。完成条件是资料与知识库可用，不强制要求接通所有平台。

## 2. 产品知识库

### 文档

建议默认文档：产品概述、用户与场景、功能清单、使用指南、商业模式、品牌与文案规范、常见问题、版本变更。使用目录和 Markdown，不引入复杂知识图谱。

文档保留状态、更新时间、来源及修改记录。AI 优化和版本更新都生成逐条差异，确认后更新；未确认建议不进入正式知识。相互矛盾、过期或缺少来源的事实需提示。

### 素材

统一维护图标、截图、演示视频、封面、品牌资源和营销配图。素材字段：产品、可选版本、名称、类型、语言、平台、文件、尺寸、上传时间、失效时间、备注。文件存储与业务记录分离，不将视频转成工作区 JSON 内的 Base64。

支持上传、预览、筛选、下载、替换和归档。到期素材自动变为过期，保留原文件及引用；AI 和新内容默认只选有效素材。已有文章引用过期素材时提示替换，不悄悄修改已发布内容。版本素材是同一个素材库的版本筛选视图，不重复上传两份。

## 3. 版本发布

版本工作区包含五步，允许返回修改，并展示真实阻塞项：

| 步骤 | 输入与行为 | 完成条件 |
| --- | --- | --- |
| 更新内容 | 产品、平台、版本号、原始更新、目标语言 | 必填信息齐全 |
| 多语言说明 | AI 翻译、手动编辑、逐语言确认、术语一致性检查 | 目标语言均已确认 |
| 商店发布 | 读取状态与构建、预览差异、写入说明、绑定构建、提交审核、跟踪上架 | 远端状态确认上架 |
| 版本素材 | 上传并关联当前版本，可设置有效期 | 所需素材已备齐或明确跳过 |
| 营销与知识 | 按渠道生成文章、按文档生成修改建议 | 草稿已创建；知识修改独立确认 |

素材和推广可提前准备，步骤不是强制串行锁。上传到 Growmory 与上传商店截图是两个操作；首期素材库用于收集与引用，商店截图上传需另做设备、语言和尺寸映射。

本地准备状态与 Apple 审核状态分别保存。商店写入、提交审核、正式上架分别预览确认。失败显示已完成步骤，重新读取后继续，不能简单重试全部操作。二进制由 Xcode/Transporter 上传，不在此方案内新增构建服务。

## 4. ASO

按产品、地区、语言维护关键词池与优化方案。

- 热词检索：查询词、来源、地区、语言、采集日期、搜索热度、竞争度、排名及相关词。真实指标依赖明确的数据提供方；缺少数据时显示不可用，AI 只提供候选词，不生成热度数值。
- 优化方案：结合知识库、现有元数据、关键词与可用表现，输出名称、副标题、关键词、描述和推广文本，附依据、修改理由和待验证假设。
- 同步商店：明确目标版本与语言，字符校验、原文对照、过期校验、预览确认和回读核对。名称等共享信息提示影响范围。
- 效果复盘：记录修改日期、字段、关键词与观察窗口，对比前后搜索来源及商店转化；同时标记版本与营销事件，不把同期变化全部归因于 ASO。

## 5. 数据分析：产品趋势

连接时同步 ASO 与可用的 Apple Analytics 趋势报告，模块不读取销售日报、收入、内购或财务数据，不需要供应商编号。

指标为图标曝光事件、产品页浏览、首次下载、重新下载。提供 7/30/90 天时间窗、截止日期、来源与地区筛选、等长前期对比、曲线和每日明细。所选期间或前期覆盖不足时不计算完整期间增幅，缺失日期留空。图标曝光事件来自 Discovery and Engagement 的 Impression 行，不包含页面浏览；分组去重人数不能相加作为总人数，因此当前不拼凑 Apple 后台转化率。

报告按事件 Date 汇总，较新 processingDate 替换同事件日期的旧分区，多个下载分片先汇总，避免修订数据重复累计。最近 180 天缓存到独立 SQLite 表中，支持当前与前期比较。分片下载验证大小与 MD5；签名下载链接不附带 Apple API 凭据。

产品、ASO 与趋势分别记录同步结果。权限不足、尚无报告请求、等待报告生成、部分报告可用、读取失败分别显示；失败保留上次成功数据及时间。只读模式只访问已有报告请求，不自动创建请求，报告权限与元数据权限独立。

营销关联仍按活动与版本记录，只做有依据的趋势对比，不将同期变化解释为推广或 ASO 的因果效果。

## 6. 营销与推广

内容中心：选产品/版本 → 选受众、目标、渠道与语言 → 引用知识与有效素材 → AI 草稿 → 编辑审核 → 复制或发布 → 记录链接与时间 → 读取或导入数据 → 复盘。

内容包括标题、正文、话题、图片顺序、渠道、语言、状态、计划/实际日期、发布链接、活动与来源版本。小红书侧重场景、体验、封面与图文；X 侧重短文、线程与链接。渠道适配不得编造使用体验或效果。

平台连接独立显示授权与可用能力：读取账号、读取内容、读取指标、公开发布。先接入有明确授权接口的平台；小红书不能预设存在适用于普通创作者的完整通用 API，无法确认接入时提供平台导出文件导入和手工记录。连接账号不等于自动发布授权。用户要求的是连接读数，公开发布先以复制和跳转为默认路径。

## 7. AI 的角色

| 场景 | 输入 | 产物 | 生效方式 |
| --- | --- | --- | --- |
| 初始化 | 商店资料、用户补充 | 产品资料与知识草稿 | 人工确认 |
| 版本翻译 | 已确认更新说明、术语、目标语言 | 多语言说明 | 逐语言审核 |
| 更新转推广 | 版本、场景、品牌规范、素材 | 分渠道文章 | 编辑后发布 |
| 知识更新 | 版本变化、现有文档 | 文档差异与原因 | 确认后应用 |
| 知识优化 | 当前文档、事实来源 | 去重、补全建议、冲突提示 | 确认后应用 |
| 自主选题 | 产品知识、内容记录、目标 | 选题和内容草稿 | 审核 |
| 数据分析 | 标明口径的真实数据 | 事实、假设、建议、观察窗口 | 保存分析，可转任务 |
| ASO | 知识、商店文案、实际关键词数据 | 优化方案与理由 | 差异确认后同步 |
| 内容复用 | 已发布内容、渠道表现 | 复用或改写建议 | 不覆盖原文章 |

AI 不独立占一个空白聊天页。操作嵌入具体工作区，生成任务有进度、失败重试和来源记录。MCP 与站内按钮复用业务校验；外部 Agent 不能通过本地记录写入绕过商店发布流程。

## 8. 核心数据关系

Product → Documents / Assets / Releases / ASOPlans / Campaigns / MetricSnapshots。
Release → LocalizedNotes / Assets引用 / Contents / KnowledgeProposals / PublicationEvents。
Campaign → Contents / TrackingLinks / ChannelMetricSnapshots / StoreCampaignMetrics。
Connection 独立管理凭据，业务记录只引用连接 ID。AIJob 保存输入来源、状态及产物引用，避免把访问凭据写进模型上下文。

新结构直接按目标模型设计，无需历史数据迁移层。仍应保留 revision 冲突检查、凭据隔离、商店写入复核等现有正确性措施。

## 9. 实施顺序与验收

1. 信息架构和初始化：所有主模块独立可达；产品范围切换一致；连接失败可重试。
2. 知识与素材：上传、版本关联、过期过滤、刷新持久化；AI 不引用过期素材。
3. 发布闭环：说明修改后审核失效；翻译可编辑；部分成功可恢复；文章与知识建议关联源版本。
4. 数据基础：趋势报告、日期范围、分区修订和缺失数据；报告缺失、修订、重复同步和失败保留均验证。
5. ASO 数据与推广接入：先确认数据提供方与平台授权，再实现关键词查询、活动链接和指标读取。
6. 综合分析：带证据的跨来源观察，避免重复计数与错误归因。

真实账号验收仅做读取：连接状态、App 列表、版本及本地化、ASO 原文、可用 Analytics 报告。模拟服务验证外部写入逻辑；本轮不对真实 Apple 执行创建、修改、提交审核和上架。

## 2026-11-05 初始化流程修订

产品不由用户手动创建：连接成功后自动读取全部可访问 Apple App，按 Apple App ID 导入，保存 Bundle ID、平台、版本与多语言更新快照；从可用商店版本读取介绍及营销网址。介绍保存为待确认知识文档，用户再完善产品资料。重复同步不重复创建，也不覆盖用户补充信息。新工作区空白启动；主界面默认进入初始化。批量导入现已实现，不再属于待实现能力。商店价格未读取，不填猜测值。

## 2026-11-05 ASO 第一阶段落地

ASO 已拆为现状与优化、关键词研究、竞品对比、方案与复盘四个页签。关键词按市场和语言管理，支持商店词导入、JSON 观测导入、来源/日期/排名历史、状态和搜索意图；竞品支持同市场 App ID、对标原因、页面观察及商店链接。尚未自动采集第三方关键词指标、竞品文案或截图。

优化方案保存原文、目标、修改稿、采用词及其观测、竞品和已确认文档引用。载入时重新读取 Apple；原文不同会阻止旧方案直接应用。新版界面预览回写前自动保存方案，回写成功与部分失败关联执行记录。复盘引用同产品真实趋势，并标记实际同步时间；无数据与权限不足按原状态展示。

研究资料使用独立 SQLite 表和 revision，支持刷新持久化、旧窗口冲突拒绝、产品关联隔离和 ASO JSON 导出。未接入商业数据商、不提供虚构分数；尚未实现 Apple PPO 实验管理。
