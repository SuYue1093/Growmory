# 每日营销推广

## 推广动作与检索回退

每日待办仅安排面向目标用户的推广动作。版本、上线、宣传口径核对等内部准备项由Agent自行完成；MCP拒绝新建或改名为明显内部核对项，页面隐藏旧的同类待办但不删除原记录。该规则为明确标题规则，并非通用语义分类器。

任务优先使用站外搜索工具按域名和场景检索，再访问原始帖子；搜索页403不能直接代表整个渠道不可用。空结果应更换关键词、语言或过滤条件，日期窗口逐步从7天扩展到30/90天。竞品广告不能当成用户求助，未知日期不得编造。

verification=snippet表示仅有搜索摘要，必须填写evidence；只保存真实原帖URL与摘要及访问限制。页面将其放入折叠的检索线索，不计入可参与帖子。verification=full表示原文已读，旧记录没有此字段时沿用原展示。摘要需分别统计原文核实数与线索数，数量目标不再作为成功门槛。此改动没有新增平台账号授权或绕过访问限制，真实可获取范围仍取决于Agent运行环境。

## 产品与行动结构更新

营销推广页隐藏右上角全局产品下拉，顶部将所有产品以图标和名称列出。每日任务设置改为原生弹窗，复制或保存后关闭，不保留成功提示文字。

Promotion 新增可选 subtasks（id/title/done）与 article（title/body/channel/assetNames）。大任务与子任务可以勾选，全部子任务完成后大任务完成；勾选大任务同时完成子任务。旧 body 记录保持可读，初稿与子任务需由外部 Agent 按新版提示词补充。

推广上下文 assets 仅返回本产品及通用图片名称，不返回图片 URL、Base64 或画面。文章初稿一键创建营销草稿，保存 sourcePromotionId 与 assetNames；重复转换打开已有记录，不覆盖用户修改。转换排除不存在、跨产品和重复的名称。营销编辑器支持按名称增减配图。

## 首次使用

选择产品，设置每日运行时间、时区、运营时间预算。默认09:00、Asia/Shanghai、20分钟。复制提示词给已连接Growmory MCP、支持定时任务与联网的外部Agent；提示词要求创建或更新同产品已有任务，立即执行首批搜集与待办安排。

浏览器剪贴板不可用时可展开手动复制，再保存偏好。复制或保存只表示交接准备完成，不表示定时任务创建成功。设置可重新打开，提示词要求更新已有任务，不能重复创建。实际任务的暂停、修改和删除在Agent客户端管理。

## 每日使用

- 今日待办：展示今天与以前未完成的事项，今天优先，默认三项，其余折叠；操作为打开链接、完成、忽略。完成支持可选反馈，历史中可重新安排。
- 有用帖子：按核实日期展示未处理及收藏帖子，双列卡片默认12条，其余通过“再显示”展开；支持按渠道筛选，渠道优先根据链接域名识别；操作为打开原帖、收藏、忽略；参与建议折叠展示。
- 最近更新与已处理待办：折叠保留Agent每日摘要和已处理行动，页面显示最近结果回填时间，今天尚未更新时明确提示。
- 沿用2500ms工作区同步机制，MCP回填后无需手动刷新。

## Agent任务契约

get_promotion_context返回schedule、promotionCount、最近60条按更新时间排序的promotions、recentUpdate和产品事实。记录超出返回范围时，使用list_records分页查历史及get_record读取必要正文。

每日目标10至15条有用帖子，最多20条、3件合理运营动作；明确检索小红书、X、Reddit、V2EX、知乎、即刻，尽量覆盖至少3个渠道，逐渠道报告实际检索数量与访问限制，行动总耗时不超过预算。实际访问原始页面，记录sourceTitle、checkedAt、url及参与建议；没有合适结果时如实说明。按链接、同日动作查重，保留done/dismissed及feedback，不删除历史、不重置完成状态。帖子正文用Markdown区分要点、参与方式、回复和规则；待办正文区分执行步骤、材料、完成标准和注意事项。旧纯文本记录仅增加编号和标签处的阅读分隔，不改写原文。已有Agent定时任务需复制新版提示词更新，更新界面不会自动修改外部调度任务。

全部回填成功后，使用save_promotions写入kind=review、title=每日运营更新、date=执行时区当天、status=done的摘要。同日重试更新原记录。该摘要仅表示结果回填，不表示用户执行完成；失败应报告，不写成功摘要。所有复杂研究和搜集由外部Agent完成，不调用内部AI。

## 存储与兼容

首次偏好保存在Product.promotionSchedule（time、timezone、minutes），随工作区SQLite及JSON备份保存，服务端验证时间、时区及预算；旧产品无需该字段。推广记录继续使用promotions，旧记录不删除。MCP继续沿用权限、revision及链接去重检查。

## 验证与实际边界

npm run build、npm test、node tests/promotion-browser.mjs。

浏览器使用独立临时库：覆盖首次提示词、偏好刷新恢复、模拟外部写入后的自动同步、收藏、完成反馈、重新安排、1440/768/390px布局。没有操作正式工作区或创建真实定时任务。真实Agent的任务创建、每日触发和联网检索尚未实测。

Growmory只生成交接提示词，不内置调度器，不查询外部客户端任务状态。外部任务需要原生调度能力、联网及MCP编辑权限；运行时本机服务必须可访问。电脑休眠、服务关闭或任务运行环境无法访问localhost时不能保证执行。界面不将已复制提示词冒充任务创建成功，也不将缺少帖子冒充“已完成研究”。
