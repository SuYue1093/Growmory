# Growmory 整体体验优化实施记录

日期：2026-11-05。范围为本地 Growmory 的三阶段体验改造，不涉及线上托管或真实商店发布。

## 第一阶段：信息架构与页面上下文

- 日常一级导航收敛为工作台、产品、内容、待办；设置独立保留。
- 初始化移入设置的接入向导，空工作区也可直接开始接入。
- 单个产品统一提供概览、产品资料、版本发布、商店优化、营销内容、数据表现及商店版本入口。
- ASO 和趋势详情一次只展示一个产品；跨产品数据采用统一时间范围的汇总表。
- 产品详情使用当前产品切换器，切换时保留栏目并清除旧文档选择；详情页不再显示列表级新建、导入操作。
- URL hash 保存页面、范围、产品、版本、栏目、内容状态筛选、文档、目录、发布阶段及设置分组；支持刷新、直达与前进后退。
- 从产品版本列表进入发布详情，可返回该产品的版本列表。

## 第二阶段：工作流程与关联记录

- 工作台按需要处理、继续工作、产品概况排列，数量摘要取代大型统计卡片。
- 系统提醒从待确认文档、待审核内容、未发布版本、趋势同步异常实时推导；与手动任务分别展示，共用工作台和待办的统计口径。
- 提醒直接打开原记录，确认或更新后自动消失或切换为下一项工作，不新增重复任务记录。
- 发布详情按更新内容、更新说明、商店提交、推广与归档四阶段组织，阶段可自由返回；默认根据语言确认状态选择当前工作阶段。
- 明确显示缺少哪些语言，本机准备状态与商店状态分别展示；本机发布记录操作收进折叠管理区。
- 阶段切换通过隐藏保留商店组件，避免丢失当前商店状态和操作预览。
- 产品、文档、版本、内容、任务及更新说明编辑使用 sessionStorage 暂存未保存草稿，关闭或刷新后重新打开同一对象可恢复；正式保存后清除。原记录发生变化时不自动套用旧草稿。
- 内容记录显示关联版本入口，产品内营销入口使用同一套内容记录与编辑界面。
- 设置分为连接与同步、AI 与 Agent、备份与恢复；已连接 Apple 默认显示状态，管理时再展开凭据和导入操作。
- 外部 Agent 与站内 AI 分别解释和显示状态；外部 Agent 显示开关、读写范围及最近成功调用。

## 第三阶段：布局、视觉与响应式

- 保留白灰与蓝色品牌风格，统一标题、圆角、文本对比及操作权重。
- 产品短名称用于主要标题及列表；减少详情重复标题。
- 产品概况采用紧凑列表，内容采用纵向紧凑卡片。
- 无趋势报告时收起空指标、空图表和不可用的分析区；口径说明按需展开。
- 跨产品总览统一时间范围，覆盖不足的指标显示破折号，不将缺失数据计算为零。
- 手机发布导航采用两列布局；窄屏提醒调整为网格，表格在局部滚动。
- 手机侧栏收起时不可聚焦；展开后焦点进入导航，支持 Tab 循环与 Escape 返回菜单按钮。

- 实际验证文档未保存草稿在刷新后重新打开可恢复，并可丢弃；原正式正文没有被草稿直接覆盖。

- 实际验证逐语言保存和确认，中英文齐备后阻塞提示切换为核对商店状态。
- 实际验证切换产品保留商店优化栏目，浏览器后退恢复上一产品。
- 实际验证设置 AI 分组刷新恢复、数据总览统一时间范围及无数据时留空。
- 工作台、产品、内容、待办在 1440、1024、768、390、320px 共 20 组布局检查中无页面横向溢出；另检查了 320px 发布详情。

## 验证限制

- 最后补齐的嵌套目录地址恢复、手机导航键盘焦点及提醒网格微调通过最终构建，但浏览器控制随后连续超时，未完成这几处变更的最终交互复核，也未保存最终正式工作台截图。已通过的浏览器结果来自上述实际操作，不代表全部设备验收。
- 实际 Apple 写入、审核、上架及真实模型生成没有执行；既有模拟测试通过不等同于真实账号验证。
- `tests/browser.mjs` 已适配四个主入口、发布阶段与刷新恢复，并使用自有夹具替代空的产品种子；`node --check tests/browser.mjs` 通过。本轮未整套执行该脚本，交互验证通过 CUA 执行。
- 会话草稿依赖当前浏览器的 sessionStorage，关闭整个标签页/会话后不承诺保留，不能替代正式保存。
- 本轮未修改业务数据结构或后端发布协议，没有新增外部数据提供方。
