# 运营数据导入

在「运营管理 → 自媒体账号」建立平台账号，然后打开「数据总览 → 导入数据」。将平台导出的文件拖入上传区，或点击选择文件，每次上传一个文件。核对账号后确认导入，完成后列表会自动刷新。

| 平台 | 文件 | 大小上限 |
| --- | --- | --- |
| 小红书 | 创作中心导出的原始 `.xlsx` | 8 MB |
| Reddit | Reddit 数据导出的原始 `.zip` | 9 MB |

小红书先预览笔记及指标，再确认数据截止时间和统计口径。Reddit 只读取 ZIP 中的 `posts.csv`，保留标题、正文、社区、原帖链接和发布时间。能关联现有营销内容时沿用该文章，有歧义时待确认，没有候选时创建已发布的营销内容。浏览量、分数、互动量等缺失字段显示为「—」。

## 营销内容关联

先使用平台原帖链接匹配。缺少一侧的链接时，在同平台及账号所绑定的产品范围内比较规范化标题，发布日期参与消歧。无法唯一匹配时，在数据行里选择候选营销内容。标题只用于建立关联。小红书报表优先沿用已确认关联。同账号下有唯一同标题原帖时自动归集指标；有多个同标题候选时，在数据行内确认。没有候选的报表作为独立记录展示。

历史自媒体文章可运行 `node scripts/migrate-social-articles.mjs [数据库路径]` 迁移到营销内容。迁移按账号及帖子身份去重，保留原运营数据及指标。通用账号下的文章显示为未分配产品，后续可在营销内容中设置产品。运营页面已移除「潜在帖子」模块。

## Reddit 附件字段审查

Reddit 官方导出的 CSV 压缩包（39 个 CSV）中，可用于运营统计的新增口径有：

- 账号发出的评论数，`comments.csv` 与 `comment_headers.csv` 是同一批 8 条评论，按评论 ID 去重。
- 账号投出的票数，`post_votes.csv` 和 `comment_votes.csv` 各有 8 条赞同记录。
- 导出时订阅的社区数，`subscribed_subreddits.csv` 有 10 个社区。
- 发帖覆盖社区数，`posts.csv` 的 8 篇帖子分布在 7 个社区，导入数据已保留社区字段。

以上前三项属于账号自身活动，当前导入器只导入帖子。导出没有提供逐帖曝光、浏览、收到的评论总数、帖子分数、关注者或赞同率。关注者可在运营总览的「关注者」数据右侧按账号手动更新。

## 微信公众号与稀土掘金

在运营页面选中平台，添加对应自媒体账号，再打开「导入数据」。支持选择或拖入 Excel（`.xlsx`）及 UTF-8 CSV。

报表每行填写文章标题、文章链接或发布日期，以及至少一个实际指标。可识别曝光、浏览、点赞、评论、收藏、分享的常见列名。阅读人数、送达人数、在看次数等口径不会被映射为浏览量、曝光量或点赞量。通用文章表须在文件中提供统计口径及日期。区间数据可在列表中查看，累计总览只汇总累计口径。

微信公众号可展开「使用微信公众号官方 API 同步」，选择已配置相应权限的公众号，在自媒体账号中保存 AppID 和 AppSecret，同步时自动向前扫描接口支持的历史日期。服务使用官方令牌接口与图文群发总数据接口，读取阅读、分享及收藏次数，保留统计截止日。凭据单独保存在本地 SQLite 中，AppSecret 不出现在账号响应、工作区 JSON 备份或报表中。可暂停同步，或在接口额度恢复后继续。稀土掘金使用创作者中心报表导入。

### 原生趋势报表

- 微信公众号「数据趋势概况」旧版 `.xls` 自动读取文件日期。只导入「全部」渠道的文章来源明细，阅读人数保留人数口径。
- 稀土掘金「整体分析-文章」`.xlsx` 按日期导入账号级展现、阅读、点赞、评论和收藏。该报表没有单篇文章身份，所以归入账号趋势，并汇总到运营总览。
